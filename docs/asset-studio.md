# Skins and resource packs

The desktop asset library owns copies of imported files. Removing a library item never removes the original or Minecraft's installed content. Content hashes identify duplicates; a persisted index stores names, favourites, tags, provenance and capture variants. Import accepts PNG, mcpack, zip and folders. Archives are bounded and reject traversal, symlinks and ambiguous names.

Imported skin packs are split into individual selectable skins. A shared, complete original mcpack is retained and included as `original-pack.mcpack` in original-file ZIP exports. It is removed only when its last library item is deleted. Texture editing creates a new item, preserves the selected arm model, and keeps the metadata of an existing item if the edited pixels match it. Captured skin geometry, cape, animation data, resource patch and persona metadata remain available in the original-file export.

## Desktop bridge contract

### Editable Blockbench projects

The asset model export selector supports native `.bbmodel` projects alongside the existing baked GLB/glTF/OBJ/FBX/STL formats. Choose **Blockbench project · Editable**, then automatic detection, **Bedrock Entity**, **Bedrock Block**, or **Generic Model**. Automatic detection uses the selected object's binding, including objects opened from Files. Custom blocks use `bedrock_block` and retain per-face materials. Single-texture entities use `bedrock`; entities requiring multiple active textures or polygon meshes use `free`. Explicit Entity exports reject incompatible multi-material/mesh data instead of dropping materials. Polygon meshes require Generic Model rather than Bedrock Block.

The exporter reads authored geometry instead of baking the preview. It preserves bones, empty and hidden groups, hierarchy, separate cubes, pivots and rotations, inflation, mirrored/box/per-face UVs, absent faces, signed UV extents, face rotation, material names, locators, texture meshes, and polygon topology. PNG textures are embedded. Source animation channels and Molang expressions become editable tracks, including pre/post keyframes and effect scripts. Preview poses, runtime bone transforms, culling, and texture-atlas compaction are not baked into the project.

`GetAssetModelSources` follows the selected animation/controller graph through the normalized catalog and honors explicit source paths. It avoids unrelated animation files and the truncated Files preview bridge. Original geometry, selected definitions, scripts, texture variants, and warnings remain under `export_options.craftbox`, which Blockbench preserves on normal saves. Minecraft runtime shaders, game-driven controller state, particles, and behavior-pack block transformations are not reproduced; supplied definitions remain as source data. Editor-only information absent from a resource pack cannot be reconstructed. Blockbench controls generic-mesh shading normals while source normals are retained.

The exporter targets the [official project format 5.0](https://blockbench.net/wiki/docs/bbmodel/) with separate groups and hierarchy. Conversion follows the [official Bedrock codec](https://github.com/JannisX11/blockbench/blob/ec0b2827104d0799c153bfb5f867579c0c44652f/js/formats/bedrock/bedrock.js) and [animation codec](https://github.com/JannisX11/blockbench/blob/ec0b2827104d0799c153bfb5f867579c0c44652f/js/formats/bedrock/bedrock_animation.js). Browser verification compares geometry against Blockbench's own importer and checks source preservation after saving. The Hive game-hide entity retains 26 groups, 22 cubes, one texture and one animation with 17 keyframes. The Hive pirate stool opens as Bedrock Block with one group and six cubes.

`GetAssetLibrary()` may return `blockRevision`, identifying changes to saved block components. Pack viewers reload their catalogue when it changes while retaining the selected block by name. Captured visual block components are stored separately from original resource-pack files, scoped to the exact imported pack content ID. `GetAssetDetail` and `ReadAssetFile` expose these read-only JSON definitions under `captured_blocks/`. Original-file exports retain the unchanged pack. Live session metadata is recorded against the pack instances imported from that session; validated bundled metadata can initialize a known content ID without relying on model-name guesses.

New snapshots replace complete definitions with the same identifier and retain previously known identifiers, so visiting another game mode does not discard shared-model bindings. Registry writes are bounded and atomic; changed metadata invalidates the catalogue and preview caches. Virtual definition files are inspectable but do not participate in resource-pack stack collisions. Capture associations use bounded weak keys and do not retain resource-pack objects after their session. Detail refresh waits for initial asset metadata initialization and preserves user edits.

Block preview objects may additionally return `materialModes` (material alias to Bedrock render method) and `transformation` (the authored block transformation component). Both fields are optional; absent fields retain existing rendering. Explicit block components take priority; a missing material component can inherit explicit resource-pack `blocks.json` textures, including for permutations. Resource-only bindings inferred from exact same-pack namespace/name matches carry a warning; ambiguous or cross-namespace candidates remain unassigned. `PreviewAssetObject` retains authored geometry when available and never replaces custom geometry with a native-block fallback. Object IDs remain content-binding hashes.

`GetAssetLibrary()` returns items, library bytes and detected Minecraft installations. `ImportAssets(kind, paths)` imports selected local files, with a native picker when paths is empty. `GetAssetDetail(id)` returns indexed files, diagnostics and skin metadata. `ReadAssetFile(id, path)` returns a bounded text or data URL preview; paths are relative to an owned item. `UpdateAsset(id, name, favourite, tags)` persists organisation. `DeleteAssets(ids)` removes owned copies only. `CompareAssets(left, right)` returns added, removed and modified files. `InspectAssetStack(ids)` resolves files in priority order (first wins), reports collisions and dependencies. `ExportAssets(ids, name, format)` writes PNG, mcpack or ZIP through a native save dialog. Skin pack export uses stable IDs, classic geometry and localization files. Original custom geometry remains available as an archive and 3D model. `GetMinecraftInstallations()` discovers Windows GDK/UWP stable and preview installations and storage. `ImportMinecraftAssets(installationID)` copies local resource and skin packs into the library. `InstallAssetsInMinecraft(ids, installationID)` creates an owned versioned directory in the selected game's resource/skin pack folder without replacing existing files. `ApplyAssetStack(worldID, ids)` applies a preview-only stack to a loaded scene; an empty list restores its original catalog. `SaveAssetModel(name, base64GLB, format)` uses the existing model converters.

Read and import failures are returned to the caller, never silently represented as success. Long library work stays outside the capture's event lock. File previews are capped at 16 MiB, text at 1 MiB, images at 16 megapixels; imports at 2 GiB and 50,000 files. Imported JSON permits Bedrock comments. Geometry and PBR preview identify unsupported features rather than promising identical Minecraft rendering.

The capture queue is bounded to 128 tasks and 48 MiB, with a 16 MiB per-skin payload limit. Queue pressure is recorded in diagnostics; the existing capture originals remain on disk. Shutdown flushes queued work. Preview filesystems check image dimensions from contents as well as names, including extensionless textures, before handing files to the scene decoder.

Minecraft discovery reads registered packages and XboxGames MicrosoftGame.config on local drives. GDK shared/per-account storage and older UWP stable/preview paths are listed separately. A detected application with unavailable storage can still be launched; the UI explains that Minecraft must create its data folder or that access must be checked. Package versions are displayed separately from decoded game versions and CraftBox's supported wire version. Installation checks a pack's minimum game version and creates a new CraftBox directory rather than replacing Minecraft content.

## UX

`GetSkinAppearance(id)` returns `{bodyId, variants, attachments, warnings}` for a saved skin. Identity comes from the captured player UUID, never the display name alone. The preferred body is the newest non-Persona capture, followed by the newest original character. Equipment slots are shared by UUID across these variants. This operation only reads saved library data. Optional `playerUUID` on library items lets the UI show one player row while retaining every capture in the Appearance selector. Its request cache is keyed by player UUID, pack IDs and equipment revision; late results are discarded after selection changes.

Object previews additionally expose optional `motion` (animation aliases, referenced skeletal animations/controllers, scripts, particle definitions and cape visibility) and `textureAnimation` (ordered frames, index expression and pre-animation scripts). Catalogs reuse parsed pack files for up to 30 seconds and invalidate when the pack directory changes. Cached JSON source data is limited to 32 MiB across 64 packs; larger catalogs are read without being retained. A library-wide preview cache is bounded to 32 MiB and 64 results. The two-second list snapshot invalidates immediately on index/equipment timestamp changes; callers receive copied item/tag arrays. Explicit file checks still use full validation. Animated skin pixel records retain their complete atlas; face/body animation UV offsets select frames without stretching a cropped face image.

The animation preview evaluates bounded arithmetic, degree-based trigonometry, common math/query values, weighted script animation lists and controller state transitions. Cosmetic transforms preserve authored bind offsets and follow player motion after the neutral reference has been captured. Explicit constant and item-slot bone bindings and geometry locators are supported. Chroma Crown texture arrays, emitter rate/lifetime, movement, billboard flipbooks and gradient tints render in the preview; cosmetic effects can be turned off in Pose & cosmetics. Idle preview query values stand in for unavailable live server state. Arbitrary Molang programs, all Minecraft particle components, server-driven events and shader effects are not a complete Minecraft runtime emulation. Model export still bakes the displayed mesh pose; preview animation tracks and billboard particles are not exported as animated 3D assets.

The v4 checks combine the actual saved Spindex costume and equipment (two crown layers and a jetpack), retain both original captures, and render the saved angel-wing geometry with its authored animation. Four Go checks cover runtime bindings, malformed texture expressions, snapshot isolation/invalidation and combined appearance selection. JavaScript checks cover Molang calculations, animation blending and bind transforms, including cosmetics added to a posed character. A real AssetStudio render using an IPC fixture verifies one player row, two selectable variants and one shared equipment request across variant switches. Evidence is in `tmp/appearance-v4-verified.png` and `tmp/appearance-v4-ui-verified.png`. These are local saved-data/software WebGL checks; no new live Minecraft session was started.

Reuse the existing studio toolbar, dark/light tokens, controls and dialogs. The left library provides search, sorting, favourites and selection. The centre displays a skin, selected texture/model/material or comparison. Details and export controls stay on the right. Tabs expose files, checks, versions and pack order. Minecraft integration always names the selected installation and separates the installed version from CraftBox's supported network version.

Resource packs can be applied and restored from the Render editor's Resource packs dialog. Inspect texture picks a block face, restores the renderer's world-origin offset, and reports the block state, default face mapping and readable source pack. Custom permutation/material selection is explicitly labelled; geometry-only projects need the original Bedrock world for block diagnostics and pack replacement. Preview overrides affect the 3D scene and its exports, while the 2D capture colours remain unchanged.

The private object selection context is carried as optional MotionRuntime.previewQueries through the desktop bridge and used during animation initialization and each frame. This fixes the Hive Murder Solos Male/White Rabbit geometry receiving Female/Detective Fox texture and animation state. Conditional texture choices link their target objects like array variants. Shared geometry branches do not invent a query state.

Ternary splitting respects parentheses, nesting and quoted strings; resource comparison canonicalizes Molang q./query. aliases outside literals. Preview state inference covers simple state queries, negation and numeric equality/inequality; arbitrary runtime formulas are not evaluated or guessed. Paused animation controllers resolve initial routing states with a bounded cycle guard, then freeze. Normal playback retains timed self-transitions and resets state time upon transitions.

Verification: five native tests repeated three times cover both real Hub models, bidirectional conditional variants, aliases/negation/comparisons, identical geometry branches, and all 50 prior Hive flag array variants. Fifteen browser checks compare male/female bone transforms with their own declared animation stacks over multiple playing/paused frames, exercise two-step initial routing and timed self-transitions, and render both actual models with their original textures. Screenshots and reports are retained under tmp/conditional-model-*. A scoped native/frontend review was completed. Temporary successful verification source files are removed before building the executable, with hashes retained.


## Consistent Bedrock coordinate basis (2026-11-04)

The model importer now converts native X positions/pivots and X/Y rotation signs consistently with Blockbench's Bedrock codec (https://github.com/JannisX11/blockbench/blob/master/js/formats/bedrock/bedrock.js). Animation position X and rotation X/Y use the same convention (https://github.com/JannisX11/blockbench/blob/master/js/formats/bedrock/bedrock_animation.js). Cube and polygon vertices, normals and triangle winding are converted together; signed cube dimensions retain outward normals. This replaces the previous mixture of unconverted positions with partly converted rotations/face mappings that mirrored the Hive Hide sign.

Locators, cosmetic control pivots, particle offsets/acceleration and block transformation matrices use the same basis. The renderer retains ordinary positive root scales. Mesh baking corrects winding when a posed object's world matrix has negative determinant, so one-sided GLB exports retain visible faces. A/T-pose Z directions were updated for the corrected anatomical sides; the Wave preset was verified against actual rig wrist positions.

Thirty browser checks cover a readable actual Hide sign, independent bone/locator/cube/animation matrix references, signed cubes, polygons and winding, classic/slim skin rigs, asymmetric face and limb textures, posed cosmetic alignment, A/T/Wave presets, block transforms, and two-sided Atlantis flag planes. Actual Hide sign GLB export/import retained identical visible silhouette; a posed skin/cosmetic GLB retained its bounds. This verifies local source/renderer/export behavior, not a live Minecraft capture comparison. Reports and screenshots are retained under tmp/bedrock-basis-*. Scoped code reviews were completed. Temporary successful sources are removed before the executable build, with their hashes retained.

## CubeCraft atlas textures and transparent plane backs (2026-11-04)

Unbound block geometries can now resolve textures through matching terrain-atlas keys, including named color variants, when a unique model filename identifies the family. This covers CubeCraft's `models/blocks/goodie cups` versus `textures/block/goodiecups` layout. Ambiguous model stems and textures owned by a more specific model remain unassigned. The preview labels this as an inferred binding because behavior-pack components are unavailable.

Explicit zero-thickness planes whose opposite UV rectangle is fully transparent now share the visible face's UVs on both sides. This fixes the actual Skywars Chaos trident. Two visible authored faces, two transparent faces, opaque materials, and one-sided materials retain their authored behavior. Final bone-material overrides are considered before repairing a plane. Pixel inspection is bounded and cached per image; unreadable or transformed textures are left unchanged.

Verification: native tests imported the original CubeCraft Lobby pack and decoded all six papercup color previews; an ambiguous-stem regression prevented guessed assignments. Ten browser checks exercised the actual trident, both camera sides (7,068 visible pixels each), visible/blank/opaque/one-sided counterexamples, GLB texture/sidedness roundtrip, and the original textured papercup. Evidence remains under `tmp/cubecraft-*`; temporary successful test sources are removed before release. A scoped review identified the opaque-material edge case, which was corrected and rechecked.

### Nullable native rules and error notifications

Native model objects serialize an absent bone-material list as `null`. The model builder and frontend type now explicitly accept that value as well as omitted and empty lists. This corrects the v20 `is not iterable` regression, reproduced with CubeCraft's original Alex Armor model. AssetStudio also forwards its error state (including viewport errors) to the existing bottom-right error flyouts for both packs and skins, with a stable per-document notification ID to avoid duplicate cards. The inline error remains available. Browser checks cover the actual model under all four list states and both views' error notifications, StrictMode deduplication, and dismissal/retry.

### Segmented models, orphan geometry and block texture strips

Block models ending in `_bottom`, `_middle` and `_top` can share the base terrain-atlas texture when all three siblings exist in the same directory. This covers normal and Creaking CubeCraft lampposts without replacing their authored shapes. Exact pack UUID/model path/geometry exceptions restore the unbound balloon-fire and PvP marketplace textures. Melior geometry has no image in the supplied pack or its contents list; it remains untextured with an explicit missing-source explanation. The picker adds geometry variant suffixes when the shared filename hides the actual variant.

Terrain-atlas block textures are split to the geometry's declared frame aspect rather than stretched as a complete vertical strip. Explicit flipbooks use their tick speed and numeric frame order, including repetitions; conflicting definitions, atlas variants and blending fall back to a static tile. Raw library textures and original pack files stay unchanged. Animation uses the existing TextureAnimation bridge contract, and manual variant selection freezes it. Frame semantics were checked against [Microsoft's animated block texture documentation](https://learn.microsoft.com/en-us/minecraft/creator/documents/createanimatedblocktexture?view=minecraft-bedrock-stable).

Verification: three native regressions cover ten actual CubeCraft geometries, portal frame dimensions, frame order and conflicting sequences, manual selection, incomplete families, pack UUID isolation, and missing Melior source. Thirteen browser checks render all ten models, compare textured versus plain-material output, distinguish marketplace labels, verify portal frame timing and roundtrip a portal GLB. The rendered gallery was visually inspected. Reports, logs and screenshots remain under `tmp/cubecraft-parts-*`; successful temporary test sources are removed before release. A scoped review's frame-order finding was fixed and rechecked.

### Library row deletion and bulk selection

Packs and skins expose independent checkboxes and delete buttons on each library row/card. Checkboxes change the bulk selection without opening a preview. A shared selection bar selects all filtered results, including results beyond the first rendered page, clears the selection, and shows the number of deletion targets. A row's delete button always targets that row alone, regardless of other checked items.

The confirmation dialog snapshots target IDs and displays their names and total size. Cancel sends no delete request. Successful deletion removes only the affected selection and stack IDs; unrelated checked items remain selected. Library operations disable selection/deletion controls while busy. Original-source retention follows the existing native DeleteAssets contract.

Browser verification uses the actual AssetStudio and shared dialogs with 105 fixture entries for each kind, mocking only the native library boundary. Checks cover isolated row deletion with another row checked, selection beyond the first 100 results, cancellation, filtered bulk deletion, retained unrelated selection, and both list/grid layouts. Screenshots were visually inspected; reports remain under `tmp/delete-*`. A scoped review found no important issues. Temporary successful test sources are removed before the release build.
