# Document tabs

Each of render, cinematic, packs, skins and packets owns an independent, initially empty tab session. Single click opens/reuses a clean preview, double click or editing retains it. Reopening the same source activates the existing tab. Tabs can be reordered within pinned/unpinned partitions, pinned (still closable), closed with middle click or menu, and reopened during this session. One horizontally scrollable row, full-name tooltips and a tab overview. Only one tab visible per area. Running work locks tab switches/closure in its own area, not navigation to other areas. Render and cinematic project state is independent.

The project dock reserves a fixed 36px row in every managed workspace, including empty sessions. Opening the first or closing the last document does not insert/remove the row. Overflow scrolls horizontally without increasing its height. The overview uses the standard CraftBox titlebar/body/footer, an empty state, document metadata rows and a separate reopen action.

All presentation state is part of a document's dirty baseline. Closing dirty documents offers save/discard/cancel; quitting offers one selectable list of all dirty documents. Save errors/cancellation leave documents open. Sessions never restore at startup; files explicitly opened restore saved state. Existing portable render .craftbox projects remain supported.

Keyboard: Ctrl+Tab / Ctrl+Shift+Tab switches documents, Ctrl+W closes, Ctrl+Shift+T reopens the last closed document, Ctrl+S saves and Ctrl+Shift+S saves as. Arrow keys and Home/End navigate the focused tab row. Pinned tabs stay on the left and can still be closed. A bounded history retains the latest 20 closed documents for reopening during the session; older native scene sources are released. Hidden viewports release GPU resources, except while their own export needs them.

Workspace projects retain source IDs, camera, model/variant selection, skin pose, preview/wireframe settings, filters, texture edit drafts and audio arrangement/transport settings. Audio playback pauses when leaving its area. Texture drafts are embedded PNGs; audio clips reference the original pack paths. Workspace JSON is bounded to 32 MiB. Original library content is only changed through explicit existing library actions, never through project saving. Referenced content must remain available in the local CraftBox library; these files are not portable asset bundles.

Desktop contract additions:
- SaveStudioProjectForTab(tabID, worldID, name, document, saveAs): same atomic portable archive writer, save path scoped by document tab rather than global app state.
- SaveWorkspaceProject(tabID, name, document, saveAs): atomic bounded UTF-8 .craftbox-workspace JSON; format craftbox-workspace, version 1, kind packs/skins/packets, source {id,name}, view object. References original library content/capture without modifying it. Native save dialogs choose initial/new paths. Empty return path means cancel.
- OpenStudioProject: file chooser accepts portable studio archives and workspace projects. Workspace result has workspaceId, path and document with an empty world. Invalid documents are rejected before adopting them; frontend validates the view-specific contract. Existing archive return shape is unchanged.
- All render source operations resolve the requested document ID. Closing one imported document cannot dispose a different tab's source.

Packs/Skins capture settings are a companion pane rather than a replacement page. DocumentWorkspaces always receives the actual workspace page, so the library, active preview, existing tabs and task tracking remain available while capture settings are open. A two-column layout keeps the console across the bottom; narrow windows use an overlay within the content row. Existing desktop:assets events refresh the mounted libraries and captured items can be opened immediately.

# Save completion and close-dialog feedback (2026-11-04)

Render project saving could finish successfully while the close dialog still resolved the previous React session with `busy=true`. The final close preflight then rejected the completed save and displayed an empty list with a raw `Error:` message. RenderEditor now tracks import/save operations synchronously alongside their UI state, and session Busy/Dirty getters expose the current values. Workspace document sessions likewise read their existing saving/signature refs. Actual running work remains protected; duplicate save calls are rejected.

The final preflight also rejects a selected project changed again while another project is saving, as well as newly dirty projects. Selected saves must be clean before closing; changes the user explicitly chose to discard remain discardable. The dialog retains its original project rows, displays Saved/Unsaved/Task running status, and uses the standard padded titlebar/body/footer layout. Errors have an icon and a wrapped message without the JavaScript `Error:` prefix, plus the shared error flyout. A running task uses a status notice rather than a stale error. Completed clean projects can quit without another save.

Verification reproduced the original failure with the actual RenderEditor and RenderCanvas, mocking only native scene/save operations. Six browser scenarios cover successful save-and-close, native failure and formatted feedback, retry, canceled save, real pending-save locking and duplicate prevention, and Project A changing again during Project B's save. Screenshots were visually reviewed. Reports/logs remain under `tmp/save-close-*`; successful temporary harness sources are removed before building the executable. A scoped review identified the multi-project re-edit case; its regression was reproduced and corrected.
