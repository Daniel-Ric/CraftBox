# Packet Inspector

Agreed scope: one active NetherNet session, shared with CraftBox capture commands. Native CraftBox workspace with ProxyWeb-inspired inspection, offline playback, statistics, timeline, comparisons, entities/movement, transactions, chunks, watchpoints and annotations. Intervention mode is separately enabled; packet edits, blocks, delays and explicit sends target only the active connection. Raw packet authentication data may be revealed by an explicit viewer option; normal views and exports redact it.

## Local desktop contract

This module uses the existing Wails desktop bridge, not an additional HTTP listener or a Java subprocess. The authoritative local contract is the Go request/response types and matching TypeScript definitions. Packet sequence IDs are decimal strings. Decoded JSON remains a string so 64-bit protocol identifiers are never rounded by bridge serialization.

Operations: `GetPacketInspector`, `ConfigurePacketInspector`, `QueryPackets`, `GetPacketDetail`, `GetPacketTypes`, `GetPacketAnalysis`, `ImportPacketCapture`, `ExportPacketCapture`, `UpdatePacketCapture`, `DeletePacketCapture`, `GetPacketRules`, `SetPacketRules`, `PreviewPacketSend`, `SendInspectorPacket`, `GetPacketContentLinks`, `ExtractPacketContent`. Queries specify capture ID, direction, type, offset/limit, newest-first order and optional playback packet cutoff. Pages contain at most 400 metadata rows; full bodies are loaded separately. Search supports text, `name:`, `type:`, `id:`, `dir:`, `stage:`, `action:`, `actor:`, `entity:`, `hex:`, size comparisons, quoted values and negated terms. Detail and export have separate explicit `revealSecrets` flags. Imports accept a path or use a native file dialog. Export uses a native save dialog.

`DeletePacketCapture` rejects active, finalizing and active trigger recordings. Ordinary offline reads do not prevent deletion: new snapshots are blocked, current scans are cancelled at record boundaries, and deletion waits for their file handles to close before removing the owned directory. Reader draining holds neither the store mutex nor global controller/trigger mutexes, allowing another live session to continue. Imported source files remain outside this operation. The UI suppresses obsolete results/errors from cancelled reads across mounted document tabs, clears deleted selections and retries reads if deletion fails. Inactive inspector tabs do not start new page/type/detail/analysis scans.

2026-11-04 regression evidence: three native tests repeated five times cover reader cancellation/drain, other-recording progress through Controller.Status/Observe, and active/finalizing deletion guards. 27 Chromium checks cover fixed docks in all five areas, empty/populated overview layout, in-flight scan deletion, late cancellation after failure, retry and narrow windows. Desktop calls in the browser harness are fixtures; native tests use real temporary archive files. Reports and screenshots are retained in `tmp/tab-delete-*`.

Live ingress observations and intervention decisions are distinguished from outbound/generated observations. Archive files contain bounded independently compressed records plus a fixed-width seek index and lightweight metadata. Disk and queue limits produce visible gaps; they never silently count dropped observations as recorded. Playback is offline; sending requires the separate intervention mode and the current connection generation.

## Use

Open Packet Inspector, select the same NetherNet source/account used by the other CraftBox modules, and choose Start NetherNet. Minecraft connects through CraftBox's existing listener. The module runs inside CraftBox: neither ProxyPass, ProxyWeb, Java nor a separate web server is required. One live connection is supported. The other capture commands also attach the inspector; its recording switch is independent of legacy pcap2 capture. Standalone inspection avoids creating a duplicate legacy capture by default.

Inspector settings select additional worlds, packs and skins capture for the next capture start. The current command continues its own module. Live following can be paused independently from recording. Selecting/searching keeps the current view stable; Refresh or Follow live updates it. Packet type counts use a bounded cache rather than repeated full-archive scans. Heavy analysis is explicitly refreshed, and playback analysis uses the selected prefix. Playback steps through observations at the chosen packet rate; it is not a network server replay or an emulation of Minecraft state.

Received and sent records describe distinct observations at the proxy's endpoints. Stored bodies are decrypted Bedrock payloads; the header is reconstructed from the codec's parsed packet ID and subclient fields. Sent means an encoder observation, not a transport delivery acknowledgement. Byte counters exclude the Bedrock header. WebRTC/DTLS transport frames and unrelated account-service HTTP traffic are not recorded. Decoding follows the installed Bedrock codec; unknown or malformed bodies remain available as raw data with partial-decode labels. The vendored Optional JSON implementation now preserves present values and represents absent fields as null, while accepting legacy empty-object unset values.

Default record limit is 4 GiB per archive, configurable from 16 MiB through 1 TiB. Individual uncompressed archive records are capped at 32 MiB; the observation queue is capped at 1,024 entries and 64 MiB. Record and queue limits are reported as gaps. An exhausted recorder stops continuous recording while forwarding continues. Archive reads use independent handles, CRC checks and fixed-width indexes; unfinished trailing records are recovered from the committed index. Deletion waits until recording/finalization and active readers finish. Only owned archive files are removed.

Authentication/handshake material, recognized key/token fields and undecoded raw bodies are hidden in normal detail, search and export. Show sensitive data reveals the retained original packet. Export has its own independent opt-in. Native archive files retain original sensitive packet data in compressed form; this is not encryption at rest. Known redacted or truncated source exports cannot recover their original content.

Blocking, decoded JSON replacement and delay apply to forwarding after spawn. Passive bookmarks and recording triggers also inspect received handshake packets. Trigger rules keep up to 30 seconds of pre/post traffic, with a 16 MiB pre-roll buffer, a cooldown and up to eight concurrent recording windows. They work while continuous recording is paused. Removing a rule prevents new matches while an already-open post window finishes. A sender preview is bound to exact serialized bytes, destination and connection generation; its token expires after three minutes and can be consumed once. Individual edited/sent bodies are limited to 1 MiB. Raw sends preserve the supplied body, while JSON sends require a supported packet type and encodable fields.

ProxyWeb schema-1 and native schema-2 JSON imports stream bounded values and preserve exact payload text and source-session IDs. ProxyPass session folders or packets.log files preserve multiline packet text; dates are inferred from the file date and midnight rollovers. Text logs cannot supply original wire sizes, bytes or structured fields and remain explicitly partial. Pcap2 versions 4/5 retain payloads and headers; decoding uses the installed codec because the container does not identify every original protocol version. Imports never modify their source files.

Identifier links lead to matching skin/pack library entries and current-session worlds. PlayerSkin and PlayerList packets can extract standalone skins with exact capture/packet provenance. Resource packs and worlds are assembled by their live capture modules. Reverse navigation opens related packet evidence from the existing libraries.
