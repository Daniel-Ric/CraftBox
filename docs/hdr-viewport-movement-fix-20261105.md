# HDR viewport movement regression, 2026-11-05

The user reported opaque terrain/buildings disappearing during navigation, with water and foliage remaining, followed by several seconds of flicker when the view stopped.

The reproduction uses the real RenderEngine, a saved native Hive scene page, the bundled daylight HDR/PMREM environment, camera movement, jitter, water-depth support and alternating navigation/idle quality. Opaque surfaces are tinted red solely to measure whether they are actually drawn. The original transition reproduces the defect: roughly 2,989 opaque pixels at rest, zero during movement, and WebGL INVALID_OPERATION (1282), repeatedly. A fixture without the HDR environment does not reproduce it, explaining why the earlier simplified verification missed the regression.

The navigation path switched renderer.shadowMap.enabled off while keeping the HDR-lit materials and their cached programs. The resulting shadow/sampler configuration was inconsistent. It also changed MSAA targets and discarded the sun shadow target whenever movement settled or restarted.

The fix keeps the shadow shader system enabled. During navigation, it freezes shadow updates only after all active shadow lights have a usable map. New lights or maps receive an initial render. Interactive movement and idle use the same zero-MSAA color targets and 1024-pixel sun shadow target; progressive subpixel accumulation still refines the resting image. Export and Full preview use the selected MSAA and shadow settings. The pipeline cache now keys both the resting effect budget and final-quality mode, so Idle→Export and Idle→Full preview cannot accidentally retain editor targets.

Browser regression checks cover repeated moving/idle frames in both orthographic Render and perspective Cinematic cameras, bundled HDR lighting, nonzero opaque coverage, no GL errors, stable editor target quality, Full preview entry/exit, and final image export quality. Artifacts: `tmp/hostname-prototype/movement-*-report.json`, screenshots and logs. `movement-red-report.json` records the original failure. `movement-export-cache-red.log` records the separate idle-to-export cache failure before its correction. The fixtures are controlled GPU evidence, not an FPS benchmark on the complete user world.
Verified release: `builds/unified-ui/Craft-Box.exe`, internal v34, Go 1.26.10, GUI subsystem 2; SHA256 `4846b8eb548ac86896063dfc3d6a202df0e945e949df36b2f7f7152da73b405e`. All 63 frontend assets match embedded bytes. Seven moving/idle frames in each editor retained opaque coverage and reported GL0; Full preview and image export used 4x MSAA/2048-pixel shadows while editor frames retained 0x/1024. Temporary browser fixtures were removed after verification, with hashes retained.
